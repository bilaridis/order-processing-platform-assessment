# AI usage

The assessment assumes AI tools are used and asks that their use can be explained, justified and
critiqued. This page is that record.

## Tool

An AI coding assistant, working as an agent with access to the repository, a shell and the .NET 10 SDK.

## How the work was split

The author set the architecture and made the design decisions: the services and their features, the
integration services, and the event-driven design with a Functions app per feature in every service.
The AI generated the code and drafted the documents to that design, and the details were worked out
together.

| Artifact | How it was produced |
|----------|---------------------|
| Solution structure: services, features, integration services, event-driven Functions per feature | **Designed by the author**; code generated by the AI to that design |
| Architecture documents, diagrams and decision records | **Decisions by the author**; text drafted by the AI |
| Azure design (ADR-0001, ADR-0003, ADR-0004, ADR-0009 to ADR-0011, reference architecture) | **Direction set by the author**; design worked out together with the AI |
| GraphQL schemas, OpenAPI file and event catalogue | **GraphQL for both presentation apps chosen by the author**; contracts drafted by the AI |
| Tests, compose file, CI workflows, Terraform | **Terraform, plan review and scanning required by the author**; written by the AI |
| High-level estimate and Azure cost forecast | **Requested and scoped by the author**; figures and risk drivers drafted by the AI |

## Decisions made by the author

| Decision | Reason |
|----------|--------|
| Microservices from the start; one function per feature, each running its command and command handler (ADR-0001) | App services in Azure can be created isolated and independent; the design is event driven |
| Azure | It is the cloud we use |
| App Service and Azure Functions on Windows service plans (ADR-0009) | Cost |
| Service plans split by demand (ADR-0010) | Order placement is the volume; retrieval and cancellation are exceptional |
| A CQRS app service between the front-end apps and the core services (ADR-0013) | Order tracking and a single entry point for clients |
| Terraform, with an artefact repository; plans reviewed and scanned (ADR-0011) | Review what is changed or added; security and quality review of the infrastructure code |
| Service Bus and an event-driven design from the start (ADR-0003) | Core services and integration services communicate by events |
| Core services and integration services for external and internal parties (ADR-0001, ADR-0006) | Integration services handle communication with external and internal parties |
| Azure SQL with controlled SQL execution, Azure Table storage per service (ADR-0004) | Controlled SQL execution against the database; stored data for every service |
| Azure Storage for blobs, files and photos with secured SAS URLs (ADR-0004) | Files are never public; access is granted per request |
| Private endpoints only where required (ADR-0009) | Their cost grows as the system scales |
| An analysis with a high-level estimate, cost prediction and cost escalation (`docs/estimation`) | Expected from the team lead and senior developer position |

## How the output was verified

- The solution **builds** with analyzers on and warnings treated as errors, and passes `dotnet format --verify-no-changes`.
- **97 tests pass** (order lifecycle, place-order use case, pricing, the order flow, the GraphQL schemas, notifications, module boundaries).
- The boundary tests were **shown to fail** when a module was deliberately made to reference another
  module's internals.
- The host was **run and exercised over HTTP**: place, idempotent retry, background confirmation,
  shipment webhook, refused late cancellation, out-of-stock, declined payment, cancellation of a
  pending order, another customer's order (404), missing scope (403), missing token (401).
- The Terraform passes `terraform validate`, its module tests and the Checkov scan. The CI workflow runs green.

Not verified: the compose file was not run, nothing was deployed to Azure, and statements about
third-party products (for example the licensing of MediatR and MassTransit in ADR-0003) should be
confirmed against current sources.
